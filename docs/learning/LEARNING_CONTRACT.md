# 教学共建约定

## 目标

最终成果首先是一个工程化、可独立发布的项目，同时你能够：

- 从零画出核心架构；
- 解释关键代码和技术取舍；
- 定位常见失败；
- 在面试现场修改一个功能；
- 诚实写进简历的 SWE Agent。

学习是开发方式，不是产品定位。不能用“这是学习项目”作为缺少测试、边界、错误处理或架构记录的理由。

## 分工

AI 助手负责：

- 搭建安全、可运行、带测试的工程骨架；
- 在编码前解释设计，在编码后解释关键路径；
- Review 你的练习并指出原因，而不只是给答案；
- 维护进度、决策记录和面试题；
- 控制每阶段复杂度，避免一次生成整个项目。

学习者负责：

- 阅读每阶段指定的少量核心文件；
- 用自己的话回答阶段检查题；
- 亲手完成安排的代码或测试练习；
- 不理解时及时指出，不假装掌握；
- 简历中只采用通过阶段验收的内容。

## 五项必须掌握的能力

1. Agent Loop：模型为何能多轮调用工具以及何时结束。
2. Tool Calling：工具描述、参数、执行和结果回传。
3. 权限控制：工作区边界、危险操作识别和人工审批。
4. 上下文管理：长代码和长输出如何裁剪、压缩与恢复。
5. 修复闭环：观察、修改、测试、分析失败、再次修改。

## 阶段验收

每阶段必须同时满足：

- 代码测试通过；
- `docs/PROGRESS.md` 已更新；
- 学习者完成本阶段练习；
- 学习者能脱离文档讲清楚主流程；
- 至少完成一次针对本阶段的模拟面试追问。

没有完成验收时，可以修复缺陷和补充解释，但不继续叠加下一阶段的大功能。
