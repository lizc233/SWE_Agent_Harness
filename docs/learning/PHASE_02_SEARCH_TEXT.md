# Milestone 2：`search_text` 要点

## 它解决什么问题

`list_files` 回答“仓库里有哪些文件”，`search_text` 回答“某个标识符、错误文本或配置值出现在哪里”。SWE Agent 通常先搜索，再读取命中位置附近的上下文。

## 当前接口

```text
search_text(
    query,
    path=".",
    file_pattern="*",
    case_sensitive=false,
    max_results=200,
)
```

输出格式固定为：

```text
relative/path.py:行号:命中的整行文本
```

## 工程约束

- 只接受 workspace 内的相对目录；
- 使用字面量搜索，避免把模型输入直接当正则表达式执行；
- 文件按路径排序，保证结果可复现；
- 跳过 `.git`、虚拟环境、构建目录和非 UTF-8 文件；
- 单文件超过 1 MB 时跳过，单条匹配最多展示 500 字符；
- 最多返回 1000 条，并明确告知结果是否被截断。

## 为什么不直接调用系统 `grep`

后续可以为性能增加 ripgrep 适配器，但第一版使用 Python 标准库，能在 Windows 和 CI 中保持一致，并让路径与输出预算测试不依赖外部二进制。工具接口保持稳定后，底层实现可以替换。

## 面试表达

“代码搜索工具没有直接暴露任意 Shell，而是在 workspace 边界内执行字面量搜索。它对候选文件、编码、大小、结果数量和单行长度分别设限，并输出稳定的相对路径和行号。因此模型得到的是可复现、可继续读取且有明确预算的观察结果。”
