# Engineering Roadmap

路线按可交付能力划分。每个 Milestone 都必须产生可运行功能、自动测试、文档边界和学习者验收，而不是只增加演示代码。

状态：Milestone 1–5 已完成核心工程纵切面；Milestone 6–7 按真实评测结果继续，不为功能数量盲目扩展。

## Milestone 1：可审计的最小 Agent Loop

产品交付：模型适配协议、结构化工具调用、只读文件工具、步骤上限、离线 Fake Model 测试和 CLI。

工程准入：供应商逻辑与循环解耦；路径不能逃出工作区；未知工具受控失败；CI 覆盖 Python 3.11/3.12。

学习验收：能解释消息循环、`tool_call_id`、工具注册与执行、终止条件。

## Milestone 2：仓库发现与安全编辑

产品交付：`list_files`、`search_text`、分段读取、精确替换和原子写入。

工程准入：统一 Workspace 抽象；路径、符号链接、编码、文件大小和并发覆盖均有测试；写操作生成变更记录。

学习验收：亲手实现一个工具，并能解释 Schema、handler、错误语义和边界测试。

## Milestone 3：分级权限与受控 Shell

产品交付：allow / deny / ask 三态策略、交互审批、命令执行、超时、输出截断和进程清理。

工程准入：工具注册与授权分离；危险动作默认拒绝或审批；Windows 与 POSIX 命令边界分别测试；明确说明这不是 OS 沙箱。

学习验收：能为读取、写入、删除、网络和进程操作设计风险级别。

## Milestone 4：Git 与自动修复闭环

产品交付：工作区状态、Git diff、测试命令、失败观察、再次修改和最终验证报告。

工程准入：不覆盖用户已有修改；测试失败不能报告成功；达到预算时保留可诊断状态；用示例仓库完成端到端测试。

学习验收：能现场解释并修改“观察—行动—验证—修正”闭环。

## Milestone 5：上下文、成本与可恢复轨迹

产品交付：工具输出裁剪、上下文预算、摘要、token/费用统计、结构化 trace 和会话恢复。

工程准入：压缩不破坏 tool call/result 配对；轨迹可重放；敏感配置不进入日志；预算有硬上限。

学习验收：能解释为什么上下文不是越多越好，以及裁剪错误如何破坏模型状态。

## Milestone 6：扩展机制

产品交付：Skills、MCP、后台任务，以及有明确收益时才加入的任务分解或子 Agent。

工程准入：扩展能力按需加载；外部工具有命名空间和权限边界；并发任务有所有权、取消和结果归并语义。

学习验收：能说明什么时候应该单 Agent、什么时候值得拆分任务。

## Milestone 7：评测与发布

产品交付：小型真实缺陷集、成功率/步骤/成本/安全指标、版本化配置、发布文档和演示录像。

工程准入：指标口径可复现；失败案例保留；README 只展示实测数据；安装与最小示例在全新环境验证。

学习验收：完成架构讲解、现场功能修改、故障排查和简历表述。
