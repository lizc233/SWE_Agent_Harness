# 架构决策记录

## ADR-001：作为独立 GitHub 项目开发

决定：项目命名为 `SWE Agent Harness`，仓库目录为 `SWE_Agent_Harness`，Python 包为 `swe_agent`，不使用客服项目的名称或品牌。

原因：它是可单独发布、安装和演进的 SWE Agent 工程；原客服项目只提供工程经验参考，不构成产品依赖。

## ADR-002：第一阶段只提供只读工具

决定：Phase 1 只有 `read_file`。

原因：先看清 Agent Loop，再引入修改和命令执行。危险能力必须建立在权限系统之上。

## ADR-003：核心循环不依赖 LangGraph

决定：使用普通 Python `for` 循环组织模型与工具交互。

原因：SWE 任务路径不能预先枚举。普通循环更贴近 coding agent 的本质，也便于学习者逐行解释。

## ADR-004：测试使用 Fake Model

决定：单元测试不访问真实 API。

原因：测试需要快速、免费、可重复，并能精确构造工具调用与异常边界。

## ADR-005：使用 OpenAI-compatible 适配层

决定：第一版通过 Chat Completions 兼容接口连接模型。

原因：可适配 DeepSeek 等服务，同时把供应商协议隔离在 `provider.py`，Agent Loop 不依赖具体厂商。

## ADR-006：学习资料与产品代码隔离

决定：运行时代码、产品文档和个人学习检查点分层；学习材料只放在 `docs/learning/`。

原因：学习过程不应把仓库限制成教学 Demo，同时面试准备又需要可追踪的理解与验收记录。

## ADR-007：工具注册与权限决策分离

决定：工具携带风险级别，`PermissionPolicy` 在 handler 执行前返回 allow、deny 或 ask。

原因：系统“具有什么能力”与“当前是否授权”是两个独立问题，混在 Registry 白名单中无法表达逐次审批和运行模式。

## ADR-008：命令不经过 Shell

决定：命令使用字符串数组并设置 `shell=False`，所有执行类工具始终要求审批。

原因：避免自动赋予重定向、管道和命令连接符语义；但批准的程序仍有系统用户权限，因此不宣称它是沙箱。

## ADR-009：轨迹不保存原始工具参数

决定：JSONL 记录工具名、风险、权限、耗时、输出规模和状态，不记录完整 arguments。

原因：代码片段、命令和配置可能包含秘密。可观测性必须与数据最小化同时成立。

## ADR-010：暂缓 MCP 与多 Agent

决定：0.1.0 不加入 MCP 或多 Agent，先用真实模型扩展版本化缺陷评测。

原因：当前没有数据证明它们能提高成功率；提前加入会扩大生命周期、并发、权限和故障恢复复杂度。扩展准入见 `docs/EXTENSION_STRATEGY.md`。
